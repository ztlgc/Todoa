## 目标与推荐决策

用户目标：方便记录每天的工作，到月底和年底能回答“这段时间做过什么、哪些工作有进展、取得什么结果”，并整理出可继续编辑的回顾。

推荐保留每日富文本、任务快照、月历、草稿、图片和备份机制，重做月度与年度回顾的组织方式。采用“每日自由记录 → 可选收录重点 → 月度整理 → 年度回顾”。日常输入不增加必填客户、业务、状态、金额等字段，也不要求迁移时重新整理全部旧记录。

第一版必须同时具备每日、月度、年度的最小闭环；不能只增加几个入口而继续用全年逐日全文代替年度回顾。

## 页面组织

日记顶部保留四个主要入口：每日、月度回顾、年度回顾、搜索。周阅读保留为每日页的附加日期范围，不再与“写一天”和“做总结”混用同一套日/周/月/年按钮语义。默认仍打开今天。

### 每日页

保留左侧月历，右侧顺序调整为：

1. 日期及保存状态。
2. “今日工作记录”：沿用现有完整富文本编辑器，不改成事项表单。
3. “已完成任务”：自动归档，显示标题、时间、备注展开和来源；很多任务时可折叠。
4. “本日重点”：只有已收录内容或用户主动操作时显示；平时不占据大块空白。

编辑区空白时显示轻量提示“今天推进了什么？有什么结果或需要以后记住的事？”，提供可选插入提纲：主要工作 / 进展与结果 / 问题与体会。提示和提纲均不构成必填规则。

主功能为自由记录。没有完成任务的当天照常有价值；不能使用“当天暂无完成任务”作为整页没有工作的暗示。

从正文选中一段，或在一条完成任务上，使用“收录为重点”。出现小型编辑区：摘要默认取原文、工作主题可不填、结果说明可不填。收录是显式操作，成功才提示完成；同一任务快照重复点击打开已有重点。

重点示例：

> 完成 A 项目首轮方案评审；明确两个待修改问题，下周复审。
> 主题：A 项目；来源：2026-10-12 工作记录。

不要求所有日记、段落或任务都有主题。日常段落修改仍属于日记；重点是用于回顾的摘录，保存时明确此语义。

### 月度回顾

选择月份后同时提供“回顾正文”和“本月素材”。宽屏可分栏；窄屏使用正文/素材切换，保留用户编辑位置，切换先保存。

素材默认按工作主题展示已收录重点，无主题内容归入“未分类”。每条显示发生日期、摘要、结果说明及“查看原文”。同一主题内部按时间正序，便于理解进展。另提供按日期查阅全部原始日记，未收录重点不会消失。

回顾正文是独立可编辑文档，提供以下空白章节：主要工作、重要进展与成果、问题与经验、下月关注。用户从素材中选择条目并“加入回顾”，确定性地插入日期、原文摘要和来源，不推断业务成果，不自动把全部任务堆进正文。

已完成待办与业务成果分开理解。例如“提交申请材料”只能证明提交工作完成，不能转换成“审批通过”。重复例行任务默认收起，仍可查看每次记录；第一版不做模糊语义合并。

没有重点时展示“先查看本月日记，选择值得回顾的内容”，同时提供原始日记入口；不能把“未收录重点”呈现为“本月无工作”。

“本月原始日记”和“本月回顾”分别导出，按钮与文件名明确范围。任何搜索或主题筛选不静默改变整个导出的含义。

### 年度回顾

默认展示全年重点与十二个月的回顾入口；年度正文同样独立保存。提供两个素材组织方式：按工作主题串联全年进展、按月份查看月度回顾。全年原始日记通过单独入口按月展开，不默认挂载一年富文本和图片。

年度正文提纲：年度主要工作、重要成果与关键事件、能力与经验、遗留问题、下一年方向。支持从原始重点或月度回顾中挑选素材，并保留原始日期及来源。

有月度回顾时可以选用；没有写月度回顾时，直接从全年重点和原始日记整理。不能将年度回顾建立在“12 篇月总结必须齐全”的前提上。当前年份只表示截至当前日期的资料，跨年工作在同一主题下按发生时间查看。

同一条原始重点同时出现在月度回顾和年度素材时，按来源 ID 识别；不要把月总结与原始条目再次累计为两项成果。纯手写总结没有可枚举来源时保持为一篇文档，不猜测拆分。

### 搜索

将搜索从折叠的历史列表升级为可见入口。第一版支持关键词、时间范围、只看重点；结果显示日期、类型和命中片段，点击打开来源日记或对应回顾。后续再加主题筛选。

关键词覆盖日记正文、任务快照、重点摘要和回顾正文。纯文本搜索不承诺识别图片中的文字。第一版可以定位至任务行或正文区域；准确滚动至具体段落需要稳定节点 ID，应单独实现，不能用脆弱的字符偏移假装可靠定位。

## 数据与保存设计

### 现有权威数据继续保留

- `journal_records`：每日及已有周期文档，包括现有 `content_json`、内容版本和软删除语义。
- `journal_task_completions`：历史完成快照，不与当前任务实时绑定显示，不回写原快照。
- `journal_assets`：沿用现有图片归属、草稿和撤销保护及清理流程。

### 新增最小回顾素材层

代码中已有 `JournalItem`（`src/domain/journal.ts:25–38`）的主题、重点、发生时间和状态，以及 `summaryMaterials`（同文件第 93 行）的周期素材算法。应复用类型校验、日期处理、撤销分类和排除阶段总结的规则；但算法目前主要读取旧 items 与 text，不能不经适配就作为新正文的完整素材来源。

本方案仍推荐新增独立的 `journal_highlights`：这里保存的是“从正文或完成快照收录的摘录”，需要独立版本、来源状态、单条查询与回顾关联；旧 `items_json` 表示此前手写工作事项，且当前有 contentJson 时不再合入正文展示。如果直接把新重点 append 进旧 items，可能保存成功却在当前正文与搜索中不可见（`journalContent.ts:38–57`）。新表的理由是这些具体语义与查询需要，而非现有数据结构无法记录工作。保留全部旧事项，用户选中旧事项后可显式收录，不能把旧手写记录直接重定义为新重点。

新表至少包括：稳定 ID、发生日期、摘要、可选结果、可选主题、来源类型、来源日期/日记 ID、可选任务快照 ID、收录时的来源内容版本、独立修订号、创建与修改时间、删除标记。

正文来源保存所选摘录的文本快照，不依赖 Tiptap 字符偏移；整篇正文编辑后，重点不自动被删除或替换。来源版本发生变化时标记“原文已更新”，用户可以查看原文并主动更新摘录。手工重点与自动任务完成状态不互相覆盖。

对于来源日记移入回收站，默认不在素材查询中显示该来源的重点，已有回顾中的已插入文字保留，并标明来源在回收站；恢复后素材可见。来源任务被跨日撤销时显示撤销提示，不能继续用它自动证明成果。删除重点不删日记，也不回写任务。

月/年回顾优先复用已有 `kind=month/year` 的独立文档与内容保存能力；它们是用户写作成果，不是每次查询时重新生成的字段。为“已选素材”新增显式关联表或等价稳定关联结构，保留来源 ID、插入时文本快照和版本；设置 `(回顾ID, 来源类型, 来源ID)` 唯一约束，避免重复加入。手写正文不要求每段都有来源。

第一版主题可用经过 trim、统一判重的可选文本，不立即新建客户管理或项目管理。需要更名/合并时再新增主题实体和稳定 ID；不同主题不按相近名字自动合并。

新增表和权限必须通过新的 migration，不改已经执行过的迁移。Schema 8 升级时增加版本号，并同步数据库前置校验、备份校验、受支持恢复路径、浏览器存储版本和类型契约。

### 旧记录与旧总结

不自动将旧内容全部解析成重点。旧标题、正文、事项、图片及任务快照继续可读，用户可按需收录。旧月/年总结占用同一周期键时直接在新回顾页打开，标示为已有总结并保持原文，不能用空模板覆盖。旧周总结保留在历史；新周阅读不把旧总结再次当作每日事实。

## 查询与性能

改造当前“先读全库再筛选”路径：

- 月历读取该月日期索引和是否有内容，不读取全部正文。
- 每日按日记类型和日期取详情及快照。
- 月度/年度先读取所需重点、月份索引和总结元信息；展开某天或某月时再取正文。
- 搜索在数据层分页执行，中文匹配先保证正确性；达到实测瓶颈后再决定全文索引及中文分词方案。
- 索引依据实际 SQL 增加日期、来源和回顾关联索引；前端 Query key 包含日期范围和筛选。
- 图片维持按需读取；年度素材只显示文字和附件标识，展开才加载图片。

既有五年基准仅为 SQLite 内存库与 JS 数据路径，不代表 Windows 原生 GUI 已卡顿或性能达标。实施中使用隔离的五年虚构样本，加图片样本，在 Tauri 实际窗口量测首屏、月份切换、搜索和滚动内存。建议验收目标：加载有明确反馈、输入不被全库计算阻塞、年度首屏不创建全年正文节点及图片请求；毫秒预算在目标机器测量后确定。

## 分阶段交付

### 阶段一：可使用的完整闭环（推荐首批）

包含每日主记录、可选收录重点、关键词加日期范围搜索、简版月回顾与年回顾、来源跳转、独立回顾保存和明确的回顾/原始日记导出。月年先采用现有样式的朴素素材列表，不做图表、业绩统计、复杂主题管理或自动语义总结。

同批完成分页/范围查询、迁移和备份适配，年度页不能继续依赖默认全年全文挂载。此阶段只有在日常输入保持简单且月/年真正能整理出文档时才算完成。

### 阶段二：提高整理效率

主题筛选、同一主题跨月进展、批量收录历史重点、来源更新对比、回顾中的素材管理、例行任务精确折叠。可增加“从选中文字创建跟进待办”，但它不阻塞回顾主流程，也不自动把普通日记文字变成任务。

### 阶段三：按真实使用需求扩展

更丰富的打印与办公文档导出、附件整理、主题更名合并、用户需要的总结辅助。先观察一到两个月使用情况，避免提前加入客户档案、审批流程、业务金额、工时或打卡指标。

## Validation

### 产品验收

1. 用户无需填写分类字段，可以写入一段今天的工作，切日、离开、重开后完整保留。
2. 没有完成任务，但发生了沟通或推进工作的日期，能正常记录、收录重点并进入回顾素材。
3. 同一工作在三天分别记录启动、推进和落地；同一主题中能按顺序查看，并跳回原文。
4. 本月未收录任何重点时仍能找到并查看所有当月日记。
5. 未写月度总结也能编辑年度回顾；年度页面不会显示为没有工作。
6. 月回顾与年回顾编辑重开后保留；素材刷新、原文变化和再次打开不会重写用户的正文。
7. 同一来源重复加入不重复；原始重点与包含它的月度总结不累计为两项成果。
8. 原文修改、移入回收站、恢复、任务撤销、旧总结冲突均按上述来源规则显示。
9. 导出前可清楚知道是当前回顾、原始日记还是搜索结果；内容与按钮范围一致。
10. 升级前样本恢复、升级后备份再恢复，原文、图片、完成快照、重点及总结关联完整。

仓库检查：`pnpm test`、`pnpm lint`、`pnpm build`；Rust 使用 `cargo test --manifest-path src-tauri/Cargo.toml`，格式使用 `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`。这些命令是实施后的验收要求，本次方案编写未运行测试，不声称当前全量通过。

### Stop conditions

- 当前工作区已有变更与计划重叠时，先核对差异和现有保护行为，不回退已有整改。
- 若旧月/年总结存储或备份契约无法无损复用，先补迁移设计与兼容样本，再实现新回顾写入。
- 若新增素材无法可靠独立保存、恢复或识别来源，先解决持久化，不能用前端临时状态宣称已收录。
