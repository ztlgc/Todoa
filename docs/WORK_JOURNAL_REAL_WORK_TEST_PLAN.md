# 真实工作场景的工作日记测试设计

设计日期：2026-10-17（Asia/Shanghai）。状态：内容设计完成，已写入独立浏览器测试入口并完成载入、刷新和基础筛选核对；42 项完整用例尚未全部执行。

## 1. 场景和目标

以一家中小企业的综合项目负责人为记录者，模拟“青禾客户服务流程优化”项目及其间的日常运营工作。客户、人员、报价和业务指标均为虚构测试素材。岗位覆盖客户沟通、方案、执行、采购、费用、团队协作，避免全部样本集中在软件开发或笼统的“开会、处理问题”。

主样本使用 2026-10-19 至 2026-10-30 的两个周一至周五，共 10 个模拟工作日；这是预先编写的场景，并非已经发生的工作。周范围分别为 10-19～10-25、10-26～11-01，按自然周划分，不引入节假日调休规则。

每条记录都交代具体事项、做过的工作、成果或当前状态、后续安排。除已完成事项，还要有推进中、等待外部回复、延期、返工、临时插入和取消的工作；这些业务状态写入成果说明，不新增应用状态。

测试目标：

1. 忙碌的一天能否完整记录，手写和收录任务是否顺手。
2. 阶段进展与已完成成果能否准确表达，历史记录能否保持当时的事实。
3. 不同主题、重点和搜索结果是否方便回看，统计和导出是否一致。
4. 两周内容能否支撑有事实、有问题、有后续安排的周／月／年总结。
5. 保存、切换、刷新／重启、删除恢复和异常冲突是否保护已有内容。

## 2. 与当前功能的对应

依据 [工作日记说明](JOURNAL.md)、`JournalWorkspace.tsx`、`domain/journal.ts` 和 `JournalRepository.ts` 设计，后续执行时再次核对所测版本。

| 内容 | 测试约定 |
| --- | --- |
| 一天的记录 | 同一日期一篇日记，标题、正文、整篇主题、整篇重点和多个工作条目 |
| 任务素材 | 已完成任务按实际完成日期出现；勾选“包含未完成任务”后可收录未完成任务，这些任务当前不限定为所选日期 |
| 快照 | 收录时复制标题、备注、完成时间及来源身份；后续修改原任务不应改写已保存日记 |
| 手写事项 | 不需要先创建任务；无原任务入口，适合电话、临时协调、观察和思考 |
| 工作主题 | 整篇主题按工作主线填写，条目主题按工作种类填写；主题是单个文本值，不按多标签理解 |
| 任务清单 | 建立“客户服务改进、日常运营、供应商与费用、团队与知识”四个清单；收录默认主题来自清单名，随后手动改为表中工作种类 |
| 总结 | 周／月／年为独立记录；“整理本期素材”追加文本，仍需手动提炼，不会自动生成分析结论 |
| 搜索与筛选 | 按整篇记录命中：正文、主题、任一条目等命中时显示整篇日记，保留该篇所有工作条目 |
| 导出 | Markdown 导出当前周期内满足筛选的完整记录；检查实际文件正文 |
| 备注和资料 | 任务资料中的金额、路径、文件名、链接先作为文字测试；日记不承诺渲染任务富文本、图片或附件 |

主样本所有日期、时间使用 Asia/Shanghai；源任务实际完成时间使用带时区的时间值。任务截止日期与实际完成日期分别设置，不能用截止日期代替完成时间。

## 4. 主样本结构与录入约定

- 10 篇日记，每篇 6 条，共 60 条；每篇前 4 条收录任务，后 2 条手写。
- 每篇前 3 个任务在该日实际完成，第 4 个任务在收录时未完成：共 30 条已完成快照、10 条阶段进展快照、20 条手写记录。
- 40 次任务收录对应 40 个独立源任务。编号 `D01-1` 等为测试清单编号，来源任务 ID 由应用生成，不手工假定数据库 ID。
- 表中“完成／未完／手写”指收录时状态；未完成任务后续允许改变，但必须保留收录当时的日记表达。
- `★` 表示标记该条目为重点。共 10 个条目重点；仅 D05、D10 另将整篇日记标为重点。
- 每篇先填写“可直接使用的正文”，再按表录入条目。表内成果说明作为任务原始备注和日记初始说明；收录后可按用例追加日记专用备注。
- 主样本保存完毕后建立基线；删除、改任务、冲突和边界样本在独立副本中执行，每组结束恢复基线，避免预期数字相互污染。
