# 对公客户经理工作日记

2026-10-17：围绕银行对公客户经理的客户沟通、业务推进与后续安排改造；保留每日日记、任务历史快照及独立阶段总结。

## 使用方法

完成任务后，系统按实际完成时的本地日期自动形成当天日记，继续完成任务会追加到同一天。「今日完成 · 自动记录」保留任务标题、备注文本、完成时间、所属清单与重点状态；「工作补充 · 手动填写」继续记录客户沟通、业务进展和当天总结。自动内容独立保存，正在编辑手写草稿时也能更新，不替换用户输入。

当天误勾后取消完成，对应自动条目撤回；跨日取消完成，原日期的快照保留并注明撤销时间，阶段素材归入「完成后撤销」。重复完成请求、启动补录不重复收录。修改、移入回收站或永久删除原任务，不改写已保存的快照；主动删除整篇日记后，自动收录不会将其移出回收站，恢复时可看到完整内容。

应用启动后会检查已有任务的完成时间，补齐尚未归档的完成记录，不要求先打开日记。仅能补录仍保留完成时间的旧任务，无法还原旧版本中已清空的完成记录。没有完成任务时不额外创建空白日记；手动保存的工作记录继续保留。主任务完成时计入一项，子任务的独立勾选不单独生成日记事项，重复任务按各次生成的实例分别收录。

在一级导航进入「日记」，直接在「随手记一件」输入事项，点击「保存这条记录」归入当天。客户、业务类型、记录类型、状态、沟通内容与重点可按需填写；不要求先写标题或当天总结。记录类型包括电话沟通、客户拜访、业务推进、内部协调等。

「记录今天」将快捷表单明确切换到今天；查看历史时用「补记」或表单中的记录日期选择其他日期。已有日记会追加新事项，不替换当天其他内容；回收站中的日记需先恢复。

填写「下一步跟进」与跟进时间，可勾选同时创建待办。已保存事项也支持单独「创建跟进待办」，之后可「查看跟进」并标记完成。跟进任务的完成状态单独显示，不会改写日记中当时的事项状态。任务包含来源日期与原事项；修改其标题、备注后仍保持关联。

通过「整理当天日记」或「查看完整日记」打开宽编辑面板，补充、修改当天各项工作，并在底部填写可选的当天总结。保存操作固定在面板底部。任务素材默认只显示当天实际完成的任务，也可选择当天到期、最近七天更新或全部未完成的任务；收录后保留历史快照。

快捷记录与完整编辑的未提交输入会自动保留本地草稿，重新进入可选择恢复或舍弃；离开视图时仍会提示尚未正式保存。草稿与已保存日记分开，不随数据库备份，写入失败时会提示并保留当前输入。

「日／周／月／年」切换浏览范围。周从周一开始，月和年按自然周期计算。展开阶段总结并点击「整理本期素材」，将每日事实按已完成事项、在途业务、等待与阻塞、下一步跟进归类，追加到草稿后由用户核对、提炼和保存；不会调用 AI，也不会重复追加下级阶段总结。素材保留记录时的状态，不能直接当成当前全部业务的最新状态。年度总结中保留十二个月入口。

按客户或关键词默认检索全部历史，可切换「仅当前周期」；业务、状态、主题和重点筛选精确到同一个工作事项。命中结果显示日期与对应事项，完整日记编辑仍保留当天所有内容。「导出」与当前浏览范围一致，筛选时只导出匹配事项。删除日记进入独立回收站，可恢复，不删除源任务或跟进待办。

概览显示涉及客户、已完成事项、等待回复和有后续安排的记录数量，属于工作记录统计。系统不推算存款余额、授信批复、实际放款金额或业绩；不同业务阶段仍需在具体事项中分别记清。

## 数据规则

- 同一日期一篇日记，同一周／月／年各有一篇总结，四种记录独立保存。
- 收录任务保存标题、备注、完成时间等快照。后续修改或删除原任务不会修改历史日记。尚可找到原任务时支持查看其当前内容。
- 客户、业务、状态与跟进关联字段仍保存在原有 `items_json` 中。Schema 7 新增独立的 `journal_task_completions` 表，保存自动完成快照及撤销信息；没有对任务的级联外键，随完整数据库备份恢复，兼容 Schema 6 及更早的受支持备份。旧记录可继续读取，旧快照没有完成时间时显示“未标注”，不猜测业务状态。
- 桌面任务完成、快照写入、提醒取消与下一次重复任务生成在同一事务中完成，任一步失败会保留原任务状态。自动快照不修改手写记录的版本号；只有自动条目的日期在读取时组成日记，首次手动保存才建立对应手写记录，删除时保存删除标记。
- 已手工收录的同一完成记录不会再重复展示自动副本；收录时尚未完成的进展记录独立保留。自动记录与手写事项统一参与关键词搜索、状态筛选、导出和阶段总结。任务没有独立客户、业务字段时不推断业务结果。
- 桌面跟进通过 Main 专属命令，在同一 SQLite 事务内创建任务并写回关联；重复操作复用关联任务，关联写入失败会回滚任务创建。浏览器沿用临时任务仓库，失败重试会复用已创建的临时任务。
- 桌面端使用 SQLite `journal_records` 表（迁移 0005），随数据库备份和恢复。旧版备份通过现有迁移机制升级。
- 浏览器端使用独立的 `todoa.journal.v1` localStorage 及其 `.task-completions.v1` 快照存储，刷新后保留日记；两个开发样本使用各自命名空间。浏览器任务仍是临时数据，与桌面数据库隔离。清除站点数据会删除浏览器日记。
- 保存使用版本号检测并发修改。写入失败或版本冲突保留当前输入；损坏的存储会显示读取失败，不会静默清空。
