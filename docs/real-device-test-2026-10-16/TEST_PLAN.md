## 执行规则

- 实际功能必须从安装版界面操作，并由界面结果、重开/重启结果及必要的只读数据库核验互相印证。
- 新数据统一使用 `QA-20261016` 前缀；不修改已有 2 条用户任务。原数据一致性快照放在 `.local-test-data/native-test-20261016/before-test.sqlite`，已被 Git 忽略。
- 创建一个 QA 清单、两个 QA 标签、普通/日期/重复/提醒/富文本任务及专用日期日记。到期提醒安排在执行时刻之后 2～5 分钟，穿插其他测试等待到期。
- 依次执行：基础任务与清单 → 标签及优先级 → 日期/日历/重复 → 提醒与后台 → 日记与导出 → 设置/备份 → 重启持久化 → 经确认的恢复和清理。
- 删除、永久删除、数据库恢复只针对明确批准的测试范围；恢复前再次快照。开机启动和功能入口必须记录初值并恢复；不擅自注销、重启系统或修改隐私/安全权限。
- 支持的界面不存在时，先记录安装版本差异，再判断是否缺陷。跨显示器、真实登录自启和特定通知横幅需要相应环境；不得推测通过。
- 状态区分：通过、失败、部分通过、受限未执行。`cases.csv` 为可继续填写的逐项明细，包含步骤、预期、风险及证据。
