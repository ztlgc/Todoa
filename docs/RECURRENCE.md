# 自定义重复规则

更新：2026-10-08（Asia/Shanghai）

## 已实现的设置

- 按计划日期：每隔 1～999 天、周、月、年。
- 每周可多选星期；隔周规则以开始日期所在的周一为周期起点。
- 每月可多选日期、最后一天；可跳过周六周日。
- 每月可选第 1～5 个或最后一个指定星期，以及第一个、最后一个工作日。
- 每年选择一个月份，再设置月内日期、相对星期或首末工作日。
- 从完成时刻开始：以实际完成的本地日期和时间加上间隔；月、年遇到小月收敛到月末。提前完成也从实际完成时间计算。
- 指定多个日期：最多 366 个不同日期，沿用当前任务的时间或全天状态。
- 结束方式：持续、指定日期（含当天）、次数（1～9999，包含当前任务）。

工作日仅指周一至周五，不使用法定节假日和调休日历。新规则中，不存在的月内日期或第五个指定星期跳过；旧规则沿用原有的月末收敛行为。

## 保存与生成

当前截止日期是第一次任务。自定义面板实时显示摘要及当前任务之后最多三次安排；完成时刻模式的预览假设在计划时刻完成。先应用规则草稿，再在日期面板点击确定，才保存任务。

新规则以版本 1 JSON 字符串保存到现有 `tasks.repeat_rule` 字段，不增加数据库迁移。已有 `day:1`、`weekday` 等规则保持可读、可编辑、可执行。

字段由 `src/domain/recurrence.ts` 与 `src-tauri/src/services/recurrence.rs` 校验：计算基准、频率、间隔、开始日期、星期集合、月内日期、相对星期、工作日位置、月份、自选日期、周末过滤和结束条件。

按计划日期时，完成逾期任务会跳到当前时刻之后的下一次计划，不补建已经过去的任务。结束日期、次数或自选列表耗尽时，正常完成当前任务，不再生成下一项。

次数表示包括当前任务在内的剩余任务数：每生成下一项，该新任务的计数减一；跳过的历史日期不计次数。原任务保留其历史规则。桌面端在完成事务中复制任务和提醒，生成失败会回滚完成事务。
