# Todoa 任务详情改造计划

日期：2026-10-07。状态：已实现详情布局、时间浮层、富文本、图片资源和自动保存；验证记录见文末。

## 1. 目标与范围

将任务详情改为内容优先的编辑页面：顶部管理完成状态、日期和优先级，中间编辑标题与富文本内容，底部管理清单、标签及更多操作。保留本地数据、离线使用、完成列表和回收站语义。

本次包含：日期/时间/重复/提醒统一浮层，富文本加粗与图片，可靠的自动保存，旧数据迁移及包含图片的备份恢复。时间段、子任务、云同步不列入本次交付。

## 2. 页面结构

- 顶部固定工具栏：完成复选框、日期与提醒摘要、优先级旗帜、明确的关闭入口。
- 中间独立滚动：可换行的大标题、无边框富文本内容、已分配标签小块。空内容显示“添加内容…”。
- 底部固定工具栏：左侧所属清单；右侧内容格式入口、标签入口和更多菜单。
- 更多菜单包含移入回收站。删除入口从原顶部垃圾桶移到这里。
- 宽屏使用右侧面板；小屏使用可用满高度的详情弹层，工具栏不能遮挡编辑光标。
- 统一约 24px 内容留白、细分隔线与低强度阴影。正常状态不展开全套属性表单。

## 3. 日期与提醒浮层

### 3.1 结构

1. 快捷日期：今天、明天、下周、自定义；使用文字提示说明图标。
2. 月历：切换月份、回到今天；今天和已选日期采用不同标记，跨月日期弱化。
3. 时间行：未设置时显示“添加时间”，设置后显示例如“21:30”。支持键盘输入与选择。
4. 提醒行：无、准时、提前 5/10/30 分钟、自定义；支持多条提醒的摘要与管理。
5. 重复行：无、每天、每周、每月、每年、工作日，以及现有自定义规则。
6. 底部：确定、清除。清除日期会停止重复，并处理相关自动提醒；操作前展示会清除的关联项。

### 3.2 行为与数据

- 打开时复制已保存配置到浮层草稿。月历及各项选择只修改草稿；确定后一次提交，取消/Escape 不写入。
- 日期、重复、自动提醒必须通过 Rust SQLx 同一事务更新。保留已经触发的提醒记录，独立手动提醒按既有语义处理，避免无意删除。
- 扩展当前只允许清除重复的更新接口，支持设置/修改重复规则和 reminderOffsets。
- 支持“只有日期”和“日期+时间”：增加本地日期字段及精度区分，不能用虚构的 00:00 或 23:59 替代日期。同步更新今天/即将到来/逾期/日历筛选和重复计算。
- 有时间的任务继续存储 UTC，展示本地时间；只有日期的任务保持日期字符串，不随时区转换漂移。
- 只有日期时，配置提醒必须明确选择通知时间；不偷偷生成通知时间。
- 修改日期或重复时重新计算尚未触发的自动提醒；完成重复任务生成下一次时保留规则，取消完成不重复生成下一项。
- 系统时区改变、无效时间、过去的提醒，均提供具体提示并保留草稿。

## 4. 富文本内容编辑器

建议采用 Tiptap 的基础编辑能力，与现有 React 页面集成；不引入云服务。

第一版支持：段落、加粗、斜体、下划线、删除线、重点高亮、无序/有序列表、链接、图片、撤销/重做。选中文字显示小型格式浮条，底部格式按钮打开完整工具栏。Ctrl+B 加粗，Enter 换段，Shift+Enter 换行。

图片支持文件选择、粘贴截图、拖入文件；插入光标位置，按内容宽度缩放，点击预览，提供删除与替代文字。初期采用 PNG/JPEG/WebP，单图默认上限 10MB，并限制解码尺寸；超限提示应保留现有内容。图片加载失败显示可重试占位块。

编辑器输出结构化 JSON，明确文档 schema 版本；仅接受启用的节点和格式。粘贴外部富文本时清理不支持的样式、脚本和协议。正文显示不直接执行任意 HTML。

技术依据：
- https://tiptap.dev/docs/editor/core-concepts/persistence
- https://tiptap.dev/docs/editor/extensions/nodes/image
- https://tiptap.dev/docs/editor/extensions/marks/bold

## 5. 数据、图片与兼容

当前 notes 是最多 100000 字符的纯文本。新增 content_json/content_version 存储文档，notes 继续保留正文纯文本摘要，供任务卡片及旧接口使用。旧备注按原换行转换为段落，迁移失败不得覆盖原文。

图片第一版存入独立 SQLite BLOB 资源表，记录资源 ID、MIME、尺寸、字节数和校验值；通过任务/文档资源引用管理。JSON 中只保存资源 ID，避免将 Base64 塞进 notes。前端按需读取二进制并生成临时 Object URL，离开页面后释放。

这让现有数据库备份可以同时包含正文与图片，但仍须更新 schema 版本、迁移清单、启动校验、恢复验证及对应测试。明确较大图片会增加数据库与备份体积。

编辑过程的临时资源需保留至文档保存；清理只删除确认无引用的资源。移入回收站保留资源，恢复后可继续显示。永久删除只清理该任务独占且无其他引用的资源。重复任务复制富文本并共享不可变图片资源引用，编辑其中一项不能修改另一项内容。

浏览器调试使用临时 JSON 和 Blob 资源，保持与桌面相同交互；刷新后清空这一边界不改变。

## 6. 自动保存

- 标题和正文停止输入约 800ms 后保存；中文组合输入未结束时不提交。
- 日期浮层通过确定提交；清单、优先级、标签选择后即时保存。
- 保存后保持详情打开，以轻量状态显示“保存中 / 已保存 / 保存失败，重试”。
- 保存控制以 taskId 和修订号管理，串行写入；只更新修改字段，避免迟到请求覆盖较新的内容、优先级或日期。
- 切换任务、关闭详情、关闭应用时冲刷待保存草稿。失败保留本地恢复草稿；确认保存成功后才清理。
- 恢复草稿与数据库最新版本冲突时提供比较/保留入口，不静默覆盖。
- 完成、删除与正文保存协调：先处理待保存内容，再执行状态动作，避免任务已消失而正文尚未落盘。

## 7. 分阶段实施与验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 1 | 详情外壳和组件拆分 | 顶部/底部固定，正文独立滚动；宽窄窗口、长标题与键盘焦点正常 |
| 2 | 日期/重复/提醒模型及浮层 | 确定一次落盘、取消零写入；支持日期精度、重复编辑、提醒重新计算 |
| 3 | 富文本和纯文本兼容 | 加粗、高亮、列表可编辑；旧备注完整读取，卡片显示干净文本 |
| 4 | 图片资源与备份恢复 | 插入/粘贴/拖入、重启后显示；备份恢复图片一致，回收站和重复任务引用正确 |
| 5 | 自动保存与草稿恢复 | 中文输入、快速切换、失败重试、关闭重开不丢内容，不串任务 |
| 6 | 浏览器及原生验收 | 浏览器真实交互；桌面真实 SQLite、图片读写、重启、系统通知与备份恢复分别验证 |

实施阶段可以分别验证，但最终交付必须包含图片与格式编辑，不能把纯文本外观改动视为完整交付。安装包验证和 release 发布在实现完成后单独执行。

## 8. 主要改动位置

- TaskDetails 拆分为详情容器、工具栏、标题、富文本编辑器、底栏、日期浮层及自动保存控制。
- domain/task、TaskRepository、browserRepositories：正文 schema、日期精度和调度更新参数。
- Rust schedule/reminders：调度事务、日期任务、重复生成与资源引用复制。
- SQLite 新迁移、启动和恢复校验、图片资源服务及备份测试。
- 任务卡片/日历/日期筛选：纯文本摘要与新日期模型。

本计划不改变此前已回退的新增表单清单/标签选择，也不改变收件箱的任务范围。
