P1 表示应在下一次发布前解决的数据安全问题；P2 表示应安排近期修复的流程或资源问题；P3 表示低频边界和导出细节。探针的“通过”表示成功观察到指定现象，**不表示缺陷已经修复**。

## 已确认问题

### D01 · P1：恢复旧草稿可能删除唯一已落盘副本

- **触发**：存在旧版编辑器草稿或快捷草稿；点击“恢复草稿”时，新草稿 key 的 `setItem` 抛出 `QuotaExceededError`；在 650ms 自动保存前关闭页面。
- **预期**：新草稿或正式日记至少有一份写入成功后，才移除旧副本。
- **实际**：`persist()` 吞掉存储错误并只显示提示，恢复处理仍立即执行 `removeItem(legacyKey)`。关闭后新旧草稿都不存在，数据库也未保存；重开不再出现恢复入口。
- **影响**：异常条件下，升级前已可靠保留的客户沟通记录会丢失。新旧草稿交接不是原子操作。
- **定位**：[草稿持久化](E:/2025Code/Todoa/src/features/journal/JournalNoteEditor.tsx:46)、[恢复后删除旧副本](E:/2025Code/Todoa/src/features/journal/JournalNoteEditor.tsx:112)。
- **证据**：`workspace.probe.tsx` 的 editor/quick 两个隔离用例均复现“旧副本删除、新副本未落盘、正式保存未发生、重开无恢复”。模拟的是存储异常，没有填满用户站点空间。
- **修复方向**：让草稿写入返回明确结果；旧 key 保留到新草稿成功落盘或正式内容成功保存，再清理。保持失败原文和旧版本信息。
- **验收**：两种旧草稿均在配额异常、立即关闭、重开后可恢复；正常迁移不反复恢复旧内容；任何清理失败不影响已保存正文。

### D02 · P2：图片导入阻断自动保存后，结束导入不会重新调度

- **触发**：首张图片已插入或文字已变化，后续图片导入超过 650ms，自动保存触发时仍在导入；随后第二张失败，或者没有产生新的内容更新。
- **预期**：导入结束后继续保存当前有效内容。
- **实际**：`flush()` 遇到 `importing` 返回 false；定时器已清除，`onBusy(false)` 只更新 busy 状态，没有补一次保存。内容持续停在“待保存”，直到再编辑、切换日期或导航。
- **影响**：原文草稿仍在，不能说已证明数据丢失；但内容没有按约定进入正式日记，数据库备份也不包含这段未提交内容。
- **定位**：[自动保存调度与阻断](E:/2025Code/Todoa/src/features/journal/JournalNoteEditor.tsx:60)、[导入结束回调](E:/2025Code/Todoa/src/features/journal/JournalNoteEditor.tsx:119)、[批量图片插入](E:/2025Code/Todoa/src/features/tasks/TaskContentEditor.tsx:259)。
- **证据**：隔离 UI 探针中，导入时到达保存时点、导入结束后再等待 800ms，数据库仍为 0 条，草稿仍在。探针控制导入 busy 状态，未将网络或磁盘延迟冒充真实测量。
- **修复方向/验收**：导入由忙转闲时，检查脏内容并重新调度；首张成功、后续失败和慢导入均能最终保存；不在中文组字期间提交，不产生并行保存。

### D03 · P2：嵌套列表导出会指数级重复读取图片

- **触发**：正文图片位于嵌套的有序或无序列表中。
- **预期**：每个节点遍历一次，同一图片可复用已读取的数据。
- **实际**：`render()` 先渲染全部 children；进入列表分支后又对相同 children 渲染一次。8 层列表中的 1 个图片节点调用图片读取回调 **256 次**，最终文件却只有 1 张图片。
- **影响**：真实导出会重复访问 IndexedDB/原生 IPC、读取 Blob 并转为 Base64。较深嵌套和较大图片可能拖慢导出、放大内存占用。探针使用短字符串回调，没有实测 256 份大图的峰值内存。
- **定位**：[首次递归](E:/2025Code/Todoa/src/domain/journalContent.ts:62)、[列表再次递归](E:/2025Code/Todoa/src/domain/journalContent.ts:82)。
- **证据**：`domain.probe.ts` 校验文档有效，并断言图片回调次数为 256、导出图片出现次数为 1。
- **修复方向/验收**：列表分支复用一次渲染结果，或在分支内部按需渲染；缓存图片转换结果；1/4/8 层嵌套时读取次数保持为 1，并验证导出缩进和编号。

### D04 · P2：移除图片后，资源永久残留且没有清理闭环

- **触发**：插入图片，保存，再从正文删除图片并保存；放弃图片草稿也有同类风险。
- **预期**：在保障草稿、撤销和回收站恢复的前提下，未引用图片最终能被清理。
- **实际**：正文 UPDATE 不删除任何 `journal_assets`；浏览器图片模块也只有 add/get，没有删除与引用回收流程。当前 UI 只提供软删除和恢复，无法通过正常界面彻底处理这些残留。
- **影响**：数据库、备份和浏览器空间随反复替换图片增长；已从正文移除的图片仍可读取，也仍进入数据库备份。这是资源管理缺口，不应将编辑器“撤销”所需的短期保留误当成应立即删除的资源。
- **定位**：[正文保存](E:/2025Code/Todoa/src-tauri/src/services/journal_content.rs:101)、[图片写入](E:/2025Code/Todoa/src-tauri/src/services/journal_content.rs:131)、[浏览器图片存储](E:/2025Code/Todoa/src/data/browserJournalImages.ts:19)。
- **证据**：原生探针编译实际 Rust 日记服务，执行“导入→含图保存→无图保存”；`journal_assets` 仍有 1 条，旧图仍能读取。另有生产 SQL 与真实迁移的独立验证。
- **修复方向/验收**：设计考虑草稿与撤销期限的延迟回收；保留仍被正文、草稿、回收站使用的图片。若增加永久删除，保留必要的删除标记，确保启动补录不会使已删日记复活。

### D05 · P2：跨午夜自动跟随今天失败后不重试

- **触发**：当前跟随今天，日期变化时正在中文组字、图片导入或保存失败。
- **预期**：阻断解除后，先保存旧日期内容，再在用户仍选择“跟随今天”的情况下切换。
- **实际**：跨日 effect 只依赖 `today`。`prepareLeave()` 返回 false 后，输入结束、导入完成或重试成功不会再次触发该 effect，仍留在前一天。
- **影响**：新一天的工作补充可能继续记在昨日；新完成任务归入今天，用户看到的手写内容和自动记录落在两天。
- **定位**：[跨日 effect](E:/2025Code/Todoa/src/features/journal/JournalWorkspace.tsx:46)、[组字时拒绝离开](E:/2025Code/Todoa/src/features/journal/JournalNoteEditor.tsx:64)。
- **证据**：隔离 UI 探针改变本地日期，合成 composition 阻断切换；组字结束并保存成功后，日期仍为前一天。未更改系统时钟，未将合成输入称为真实 Windows 输入法验收。
- **修复方向/验收**：记录待完成的跟随切换，在阻断结束后重试；旧内容仍保存到旧日期；用户主动浏览历史应取消自动跟随。

### D06 · P3：浏览器与桌面的正文长度上限不一致

- **触发**：一段恰好 200000 个 UTF-16 字符的正文。
- **预期**：两端对同一文档采用相同的长度规则。
- **实际**：前端投影先 `trimEnd()`，允许 200000 字；Rust 在去掉段落末尾换行前检查，计为 200001，返回 `CONTENT_TOO_LONG`。199999 字原生保存成功。
- **影响**：极长内容在浏览器可保存，桌面被拒绝；桌面 Repository 又转换成通用失败提示，用户难以定位长度问题。未发现该拒绝会覆盖既有内容。
- **定位**：[前端限制](E:/2025Code/Todoa/src/domain/journalContent.ts:35)、[文本投影](E:/2025Code/Todoa/src/domain/contentDocument.ts:7)、[原生限制](E:/2025Code/Todoa/src-tauri/src/services/journal_content.rs:76)。
- **证据**：前端探针接受 200000 字；实际 Rust 服务的原生探针拒绝同样字符数，并接受 199999 字。
- **修复方向/验收**：统一去尾空白、段落分隔和 UTF-16 计数顺序；验证上限前后、表情符号及多段落，返回可操作的错误信息。

### D07 · P3：代码块导出会修改尾部空白

- **触发**：粘贴或编辑包含行末空格、末尾空行的代码块。
- **预期**：代码块逐字保留。
- **实际**：导出代码块调用通用 `plainText()`，其 `trimEnd()` 删除原文尾部空白。
- **影响**：导出保真度问题；对普通客户工作记录影响较小，不应抢占前面问题的优先级。
- **定位**：[代码块导出](E:/2025Code/Todoa/src/domain/journalContent.ts:86)、[去尾空白](E:/2025Code/Todoa/src/domain/contentDocument.ts:10)。
- **证据**：探针输入 `第一行\n第二行  \n`，导出后末行空格和空行消失。
- **修复方向/验收**：代码块使用保留空白的文本提取；文本、缩进、末尾空行和代码围栏可回读一致。
